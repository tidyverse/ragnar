# Find links on a page

Find links on a page

## Usage

``` r
ragnar_find_links(
  x,
  depth = 0L,
  children_only = FALSE,
  progress = TRUE,
  ...,
  url_filter = identity,
  validate = FALSE,
  get_timestamps = FALSE,
  include_root = FALSE,
  metadata = FALSE
)
```

## Arguments

- x:

  URL, HTML file path, or XML document. For Markdown, convert to HTML
  using
  [`commonmark::markdown_html()`](https://docs.ropensci.org/commonmark/reference/commonmark.html)
  first.

- depth:

  Integer specifying how many levels deep to crawl for links. When
  `depth > 0`, the function will follow child links (links with `x` as a
  prefix) and collect links from those pages as well.

- children_only:

  Logical or string. If `TRUE`, returns only child links (those having
  `x` as a prefix). If `FALSE`, returns all links found on the page.
  Note that regardless of this setting, only child links are followed
  when `depth > 0`.

- progress:

  Logical, draw a progress bar if `depth > 0`.

- ...:

  Currently unused. Must be empty.

- url_filter:

  A function that takes a character vector of URL's and may subset them
  to return a smaller list. This can be useful for filtering out URL's
  by rules different than `children_only` which only checks the prefix.

- validate:

  Default is `FALSE`. If `TRUE`, checks that local files exist and sends
  a `HEAD` request for each remote link, removing those that are not
  accessible. Requests are sent in parallel using
  [`httr2::req_perform_parallel()`](https://httr2.r-lib.org/reference/req_perform_parallel.html).

- get_timestamps:

  Default is `FALSE`. If `TRUE`, sends parallel `HEAD` requests for any
  discovered URLs that were not visited during crawling, and records
  their `Last-Modified` response header. Sitemap `<lastmod>` dates and
  datetimes are recorded without extra requests; only missing or invalid
  sitemap dates need `HEAD` requests. Pages fetched during crawling use
  the `GET` response header when present and retain their sitemap date
  otherwise. Useful for incremental ingest: callers can skip re-fetching
  pages whose timestamp has not changed since the last run. Note that
  not all hosting platforms set `Last-Modified`; S3-backed sites
  (including many `docs.posit.co` pages) and GitHub Pages do, while
  Netlify-hosted sites (e.g. `quarto.org`) do not. Missing headers and
  local file timestamps are recorded as `NA`.

- include_root:

  Default is `FALSE`. If `TRUE`, also includes the starting page in the
  results, subject to `children_only`, `url_filter`, and `validate`.
  Sitemap inputs contribute only their listed URLs. If `FALSE`, the
  starting page can still be returned when it is found through a link.

- metadata:

  Default is `FALSE`. If `TRUE`, returns a tibble with a character
  `source` column and a `POSIXct` `last_modified` column, with one row
  per returned link. Missing timestamps are `NA`. This does not request
  additional timestamps; use `get_timestamps = TRUE` for that.

## Value

By default, a `ragnar_links` object: a character vector of URLs, sorted
alphabetically and deduplicated, with the following attributes:

- `last_modified`:

  A named `POSIXct` vector of timestamps from response headers and
  sitemap entries. Always present. URLs without a known timestamp are
  `NA` or absent from this vector; `metadata = TRUE` gives every
  returned link a row with `NA` for an unknown timestamp.

- `problems`:

  A data frame with columns `link` and `problem`, present when a link
  could not be fetched or validated, or a sitemap entry lacks an
  absolute HTTP(S) URL.

Joins and row-binding combine links as ordinary character vectors. To
keep timestamps in the combined data, use `metadata = TRUE`. This
returns a tibble with `source` and `last_modified` columns in the same
order as the default vector. Both return types retain the `problems`
attribute when present, including problems for links excluded from the
results.
